## Edge coverage and flagged assumptions (spec-less probe fallback)

Resolved with explicit acceptance (authored into `must_haves.truths` above):

- **FOUND-06 empty** (resolved, explicit): no tokens, no partial chips, split count 0, no note. Tests: regression `empty` fixture and counts tests.
- **FOUND-06 encoding** (resolved, explicit): "partial" means the token's bytes are not valid UTF-8 alone (strict TextDecoder, ignoreBOM true); "split character" means a grapheme containing a multi-byte code point whose bytes span more than one token. Measured expectations are fixed in the tests (emoji example 2, ZWJ family 1 with 18 partial chips, cafe precomposed 1, e plus combining accent 1, Japanese 3, plain ASCII 0, lone surrogate 1).
- **TOK-02 empty** (resolved, explicit): counts read 0, 0, 0.
- **TOK-02 encoding** (resolved, explicit): characters are grapheme clusters (Intl.Segmenter), words are word segments containing a letter or a number (this deliberately differs from the literal "word-like segments" wording in UI-SPEC because Firefox reports CJK segments as not word-like; for ASCII text the result is identical; research Pitfall 5), tokens include partial pieces.
- **TOK-03 boundary** (resolved, explicit): ids 0-255 are raw bytes, merges start at 256, the maximum id is 255 plus the merge count.
- **TOK-03 precision** (resolved, explicit): the only tie-breaking is in training and is the recorded deterministic rule; there is no rounding anywhere.
- **TOK-03 concurrency** (resolved, explicit): tokenize is synchronous and pure; no shared mutable state after creation.

Unresolved and flagged (unclassified by the edge probe, never auto-resolved):

- **FOUND-03 (unclassified, unresolved, flagged assumption).** "Whitespace made visible" is read as: ASCII space, line feed and tab get the glyphs U+2423, U+21B5 and U+21E5 (UI-SPEC); other C0 controls get Control Pictures; non-ASCII whitespace (no-break space, ideographic space, zero-width characters) appears inside hatched partial chips as hex bytes because every non-ASCII byte is its own token. No other whitespace class is specified. Real-device glyph coverage on iOS and Android is not verified in Phase 1 (non-blocking, D-15 amended; carried in the deferred note); desktop glyph rendering is a manual check in Plan 04; the one-line fallback to a middle dot is the glyph constants in `src/core/display.ts`.
