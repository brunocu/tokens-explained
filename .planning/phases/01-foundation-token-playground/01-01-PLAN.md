## Phase Goal

**As a** reader with no programming background, **I want to** open the "What is a token?" post (served locally in Phase 1, deployed in Phase 5) and play with a tokenizer in my browser, **so that** I come away with a correct mental model of what a token is.

Source: ROADMAP Phase 1 Goal plus the PROJECT Core Value. The ROADMAP Goal line is not in canonical user-story form, so the story above is assembled from those two lines without adding new scope; run `/gsd-mvp-phase 1` if you want the ROADMAP line normalised.

This plan's slice (the Walking Skeleton): a reader opens the statically built site and sees chips produced by the real byte-level tokenizer, and can type to re-tokenize. Every layer is touched once: dev environment, scaffold, base-aware URLs, fonts, MDX and Svelte integrations, pure-TS core, island hydration, guards, local static serving.
