# Phase 3: Known limitations

Things that are not verified, are accepted as they are, or are recorded for later (D-15). A manual check that could not be done lands here with the status **not verified** and does not block release. Statuses: **not verified**, **accepted**, **backlog**.

| # | Limitation | Status | Reason or what it means for a reader |
|---|---|---|---|
| 1 | GitHub Pages serves each file with a 10-minute browser cache and delivers gzip only (no brotli). | accepted | Pages offers no setting for either. After a deploy, a reader may see the old version for up to ten minutes, and the GPT-2 file is 557 KB over the wire instead of the 444 KB it would be with brotli. Sizes in `03-PERFORMANCE.md` are gzip for that reason. |
| 2 | The OHCHR pages, the ACM page (`doi.org/10.1145/1187415.1187418`) and the OpenAI blog page block scripts, so the automated fact check could not open them and they have to be checked by hand. | not verified | Their terms and the Arabic sentence were read by the author in a browser (checklist item 4); the metadata of the ACM article was confirmed through Crossref. Until the author has run checklist items 4a and 4g, these stay "not verified"; update this row with the result. |
| 3 | iOS (iPhone Safari) and Android (Chrome) rendering of the space, new-line and tab symbols and the 360 px layout. | not verified | The author has no iOS device and may not have an Android one. If checklist item 3 is not run on a device, this stays "not verified". The fallback is a one-line change to the three glyph constants in `src/core/display.ts`. |
| 4 | The mobile layout is secondary. | accepted | Desktop widths (1280 and 768 px) are the verified targets. The phone checks are non-gating (`*.secondary.spec.ts`); small layout issues on a phone are backlog, not release blockers. |
| 5 | The JavaScript tokenizer (`@huggingface/tokenizers` 0.2.0) was compared with the Rust reference on 28 curated cases only. | accepted | Phase 2.1 item 2. The playground presents GPT-2 output for any text a reader types; a rare regex feature the JavaScript library cannot reproduce could give a different split on an unusual input. The declined idea is to widen the golden file (`src/core/fixtures/adapter-parity.json`) with more cases. |
| 6 | The fonts come from Fontsource and are fetched at build time, then served from the site itself. | accepted | No request goes to a font host at reading time (checked by `check:dist` and the privacy spec). A build with no internet access cannot fetch them. The licence (OFL-1.1) notice ships with the site. |
| 7 | Lighthouse is report only. | accepted | The four scores are written down (checklist item 8) and nothing passes or fails on them (D-11). The performance budget in `03-PERFORMANCE.md` is also a report, not a gate (`03-DECISIONS.md`, item 4). |
| 8 | Time until the textbox is typable on a slow network is an arithmetic estimate (about 4 to 5 s), not a measurement. | accepted | `03-PERFORMANCE.md` explains it. The measured part is CPU slowdown only (`03-HARDENING.md`, Freeze: about 0.7 s at 4x CPU throttling on a local server). |
| 9 | The print rendering was checked automatically (a 17-page PDF is produced) and by looking at the first screen of the post under print styles. The widget pages of the PDF were not looked at by the assistant. | not verified | Checklist items 4c, 4f and 5 are where the author looks at the printed result. |
| 10 | The playground and the comparison's own-text block retry a failed download independently, so a reader who sees both fail presses Try again twice. | accepted | Phase 2.1 item 5, "not a defect today". Checklist item 4d asks whether it reads acceptably; if the author says it does not, this becomes backlog (one shared retry). |
| 11 | The reader readings (two non-programmers) happen after deployment and release does not wait for them (D-22). | accepted | Confusion points found will be recorded in `03-READER-QUESTIONNAIRE.md` as fixed or backlog. Two readers find the most glaring problems, not all. |
| 12 | Screen reader testing covers one combination (assumed NVDA or Narrator with Chrome or Edge on Windows). | accepted | VoiceOver (macOS, iOS) and TalkBack (Android) are not checked. The automated axe scans in light and dark, and the keyboard tests, gate every release. |
| 13 | Items found by `03-HARDENING.md` marked backlog. | accepted | None: the automated checks of 2026-10-14 (reflow, print, dark, freeze, privacy, npm audit) found no defect. The npm audit advisory (`http-cache-semantics`) was fixed with the plain `npm audit fix`, not accepted. |
