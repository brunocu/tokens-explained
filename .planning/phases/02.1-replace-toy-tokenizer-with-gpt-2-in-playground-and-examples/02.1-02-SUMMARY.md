# Phase 2.1 Plan 02: Playground failure state, truthful legend and GPT-2 unit tests Summary

**The playground now reports a failed GPT-2 download in plain words with a working Try again button, the legend no longer says the end-of-text marker "gave up", and a Node-only `buildGpt2()` lets the display-layer unit tests prove their invariants on real GPT-2 output.**

## Performance

- **Duration:** 8 min
- **Started:** 2026-10-07T15:12:00Z (approx.)
- **Completed:** 2026-10-07T15:20:00Z
- **Tasks:** 2 (both TDD)
- **Files modified:** 13 (2 created, 11 modified)

## Accomplishments

- `Playground.svelte`: `startDownload(retried)` drives the GPT-2 fetch. On failure it shows `data-tokenizer-load-error` and a `data-tokenizer-retry` button; the textbox stays `readonly`, the static default chips and example buttons keep working, and the loading status line is hidden. Focus goes to the button only after a reader-pressed retry fails again. A separate `data-tokenizer-live` region announces "The tokenizer is ready. You can type now."; the textbox carries `aria-busy` while loading. The runtime error element `data-tokenizer-error` is untouched.
- `specialKinds(tokens)` in `src/core/display.ts` splits a special token spelled `[UNK]` from any other special token. `TokenLegend` keeps `special` and gains `marker` with a sentence that makes no claim about giving up. `TokenDisplay` passes both flags, so the legend explains only chips on screen.
- `src/core/buildTokenizer.ts`: `buildGpt2()` reads `public/tokenizers/gpt2.json` from `process.cwd()`, imports the library dynamically, reuses `createRealTokenizer`, and memoises the promise.
- `regression`, `chars`, `counts` and `TokenDisplay` tests no longer import the toy tokenizer. Expected values were re-derived from engine output (see below).
- New Playwright test (5) in `e2e/playground-load.spec.ts` aborts the GPT-2 request twice and checks message, locked textbox, focus rules, recovery and the ready announcement.

## What GPT-2 does differently (values re-derived from the engine)

- Emoji example: 9 tokens, 3 partial, 1 split character (was 8 partial, 2 split under the toy).
- ZWJ family: 10 partial tokens (was 18). Japanese 日本語: 6 partial tokens in 3 frames of 2 (was 9 tokens).
- Lone surrogate: one whole replacement-character token, not partial, no frame (was 3 partial). Zero-width space and precomposed é also get no frame.
- Typed `<|endoftext|>`: one special token, id 50256 (was plain text).
- 1,000 CJK characters: 2,000 tokens (was 3,000), first cell "Bytes 1 to 2 of 3 of 日".
- 男女 こんにちは: 3 frames, 6 hatched chips, 4 whole chips (was 7 frames, 21 hatched).
- The invariant "a token is framed exactly when it is partial" held for every corpus entry and the fifth example with no exception.

## Decisions Made

- `TokenLegend` keeps `special` for the [UNK] sentence so the comparison, languages and own-text callers still compile; `marker` is additive.
- The failure message is inside an always-present `role="status"` wrapper (announced when it appears); the Try again button sits outside it.
- A minimal `process.cwd()` declaration was added to `src/node-builtins.d.ts` rather than adding `@types/node`, matching the existing approach for `node:fs`, `node:crypto` and `node:zlib`.
