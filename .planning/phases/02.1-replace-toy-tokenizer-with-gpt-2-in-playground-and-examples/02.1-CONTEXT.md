<decisions>
## Implementation Decisions

### Settled by the quick-task evaluation (carried forward, not re-asked)
- **D-01:** Option A "full swap, stepper kept": GPT-2 powers the playground, prose figures and examples. Comparison and languages table become GPT-2 vs BERT (toy row/column removed). Source: `.planning/quick/261006-riu-evaluate-dropping-the-toy-tokenizer-from/261006-riu-EVALUATION.md` section 10.
- **D-02:** The BPE stepper (`bpe.ts`, `stepper.ts`, `BpeStepper.svelte`) stays and is relabelled as a miniature that learns from one sentence and stops after ten merges.
- **D-03:** Self-hosted GPT-2 and BERT files, the `@huggingface/tokenizers` adapter and `loadTokenizer.ts` as sole `fetch` site stay as built in Phase 2 (Phase 2 D-08, D-09).

### Playground loading
- **D-04:** The playground fetches GPT-2 **automatically on page load** (reader's choice over `client:visible`). Typing never triggers a request; only arrival does. The planner must make the island hydrate early enough to start the fetch at page load, keep the tokenizer file out of the JS bundle (fetch, not import), and note the Phase 5 initial-load budget impact for criterion 4 (the file is 0.55 MB gzip, 0.44 MB brotli).
- **D-05:** While GPT-2 loads, the **textbox is locked** and a one-line status explains it (for example "Loading the tokenizer, about 0.5 MB"). Only the textbox is locked: example chips, the Token IDs toggle and Reset stay usable on the server-rendered default text. This means the server-rendered props must carry the default text's ids as well as its token text, so the toggle works before GPT-2 arrives.
- **D-06:** On failure the playground shows an error with Try again (modelled on the own-text block's `data-own-error`), the static default chips stay visible, and the textbox stays locked until a retry succeeds.
- **D-07:** Two-level state: the island reports `data-state="ready"` as soon as it hydrates, and a separate sub-state (for example `data-tokenizer="loading|ready|failed"`) covers the download, so the 8-second island failure watcher in `BaseLayout.astro` is not tripped by a slow connection. The default text's chips are server-rendered from props (default text added to the committed comparison fixture generation, so it gets the existing freshness test) so the no-JS page and `check:dist` still see `data-chip`.
- **D-08:** `loadTokenizer` gets a per-id memoised promise so the playground and the own-text block share one request and one built instance.
- **D-09:** The comparison's own-text block shows the **GPT-2 row live with no button** (GPT-2 is already loaded or loading) and loads **BERT only on an explicit click**, with the button label showing BERT's size. Typing alone still never triggers a request. This supersedes Phase 2 D-10's single combined "about 0.7 MB" button.

### Default text and claims
- **D-10:** `DEFAULT_TEXT` is **unchanged** ("Tokenization splits unusual words into pieces, but common words stay whole."). With GPT-2 only "Tokenization" splits (`Token·ization`); the reader accepted the slight overstatement ("unusual" stays whole) and the rare-word example chip carries the stronger splitting demonstration. The planner must not write lead-in or caption prose that asserts more splitting than GPT-2 produces.
- **D-11:** Build-time claims (`claims.ts`) are re-implemented over GPT-2 tokens. How is the planner's call, but a false claim must still fail the build.

### Stepper-to-GPT-2 bridge and caveats
- **D-12:** After "What the step by step example showed", add a **build-time GPT-2 figure** of the same sample sentence (count from the engine, not hand-typed) plus one paragraph: the example stopped after ten merges; GPT-2's list is far longer, so it already has a piece for every word (13 tokens for the cat-sat sentence against the stepper's 20 pieces).
- **D-13:** The id-numbering caveat is **one sentence plus a build-time example**: the stepper starts its ids at the 256 byte values (`t` = 116), GPT-2 numbers its starting symbols in a different order (`t` = 83), so the same token has different ids. The example numbers must come from the engine (the content test forbids uncited hand-typed numbers).
- **D-14:** The "older tokenizer" note **explains why GPT-2 was chosen** for the playground over newer GPT tokenizers: small size, free licence (MIT), and open design. The post also says newer models cut text differently (digits, non-English). Every claim needs a citation or build-time fact; the researcher must verify the size and openness wording against primary sources (Phase 2 D-08 already says the two tokenizers were chosen because they are small and openly licensed).
- **D-15:** The stepper lead-in sentence (pinned as `STEPPER_SLOT_SENTENCE`) gets a short addition saying this is a miniature learning from one sentence; the pin and its test are edited together.

### Deletion scope and requirements
- **D-16:** **Delete all toy code**: `toy.ts`, `toy/merges.json`, `presplit.ts`, `scripts/train-toy-bpe.ts`, `scripts/lib/bpe-train.ts`, `scripts/corpus/*`, `prepare-corpus.ts`, toy tests, and the `train:toy` and `prepare:corpus` npm scripts. Re-home the hand-computed Sennrich tie-break golden (`low lower newest widest`: `[es]` then `[lo]`) as a `trainOnPieces` test inside `stepper.test.ts` so the `.claude/CLAUDE.md` golden requirement survives. Update `check-core.mjs`; move `isValidUtf8` out of `toy.ts`.
- **D-17:** **Amend FOUND-07 and TOK-07 text, set both Pending, remap traceability to Phase 2.1, and flip to Complete only when this phase verifies.** Apply the ROADMAP edits and PROJECT.md edits listed in evaluation sections 7.2 and 7.3; Phases 1 and 2 stay Complete with an "amended by Phase 2.1" note. Close the toy-corpus deferred items as superseded.
- **D-18:** Parity coverage stays at the existing **28 cases**; only the default-text case is regenerated if `DEFAULT_TEXT` changed (it does not, so verify and leave it). The residual risk (library vs Oniguruma regex on arbitrary text) is accepted.

### Verification
- **D-19:** A **human-gated non-programmer read-through** of the rewritten passages (bridge, id sentence, GPT-2 explanation, "real tokenizer" section) is the final task of this phase, after any author-notes slot, mirroring Phase 2 D-18. FOUND-07 and TOK-07 flip to Complete only after it and the full gate pass (three-browser matrix, offline and retry check on the playground, screen-reader re-read, visual check of chips holding a space plus partial bytes).

### Claude's Discretion

- How `claims.ts` is rebuilt (D-11) and what the renamed figure component (replacing `ToyTokens`) is called.
- Wave order; the evaluation's section 12 outline (tracer first, then harden, prose, comparison, delete, requirements and gate) is a good starting point.

## Existing Code Insights

### Reusable Assets
- `src/core/realTokenizer.ts` adapter and `public/tokenizers/gpt2.json`: already shipped, parity-tested, already handles partial-character chips and special tokens.
- `TokenDisplay.svelte`, `TokenTable.svelte`, `Chip.svelte`, `TokenLegend.svelte`: token-shape generic; the display layer needs no change (evaluation 5.5), only a legend line for special chips in the playground.
- `OwnText.svelte` two-level state (`data-own-state`, `data-own-error`, Try again): the model for the playground's tokenizer sub-state.
- `src/core/compare/comparison.json` freshness test: reuse for the playground's server-rendered default tokens.

### Established Patterns
- Browser-only work (fetch, window) happens in `onMount`, never at component top level (components also run in Node at build).
- Prose numbers come from the engine or a citation; the content test forbids hand-typed counts.
- Pinned sentences in `post-content.test.ts` and e2e specs: editing prose means editing the pin in the same change.

### Integration Points
- `Playground.svelte` currently calls the synchronous toy `tokenize` in `$derived`; becomes props plus async loaded tokenizer.
- `ToyTokens.astro` (build-time figures) needs a Node-side GPT-2 helper; registered in `PostLayout.astro` and the content test's closed vocabulary.
- `Comparison.svelte`, `LanguagesDemo.svelte`, `TokenRows.svelte`, `LanguagesTable.astro` hard-code the toy row (about 12 sites).
