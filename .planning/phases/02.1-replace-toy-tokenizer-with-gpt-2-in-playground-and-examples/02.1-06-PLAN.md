## Goal

A reader of the comparison card types any text and immediately sees GPT-2 cut it live, and chooses whether to download BERT (about 0.2 MB) to see the second row.

Source: D-08, D-09 (supersedes Phase 2 D-10's single "about 0.7 MB" button), D-06; RESEARCH G4.

## Flagged assumptions and planner choices

- Block states, kept close to the old names so hooks stay recognisable: `data-own-state` is `loading` while GPT-2 is pending, `error` when GPT-2 failed, `ready` once GPT-2 is available; a second attribute `data-own-bert` is `idle`, `loading`, `ready` or `error`. The load button (`data-load`) is BERT's only; retry buttons (`data-retry`) say which tokenizer they retry through a value (`gpt2` or `bert`).
- The own-text block calls the memoised `loadTokenizer("gpt2", baseUrl)` when it hydrates. If the playground already loaded the file this resolves at once; if the playground's download failed, the entry was evicted and this makes one new request. Each island's Try again is independent; whichever runs second is instant because the memo holds the file. The SUMMARY records this behaviour; unifying the two islands' states is out of scope.
- The textbox is seeded with the picked example's text when GPT-2 becomes available, as before.
- The legend uses `specialKinds` (plan 02.1-02) over the rows on screen, so GPT-2's end-of-text marker never gets the [UNK] sentence.
