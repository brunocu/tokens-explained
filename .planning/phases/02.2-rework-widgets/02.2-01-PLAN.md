## Goal

Before any widget changes, record a trustworthy baseline and put the migration scaffolding in place (the dedicated Wave 0 task the user asked for): content-test rules that allow the new MDX shape, structure-agnostic Playwright locators, a shared layout-assertion module with a red-by-design layout spec, and self-tested check-dist functions for the new server-rendered output.

Source: D-06, D-10, D-14; RESEARCH G-1, G-3, G-4; UI-SPEC "Verification Hooks" and "Test impact".

## Flagged assumptions and planner choices

- This plan has no tracer task. The user asked for the baseline and the test migration to come first, and a baseline must run on the unchanged tree. The tracer is the first task of the first implementation plan (02.2-02), which satisfies the tracer-first rule for the phase's implementation.
- The layout spec starts red for every widget on purpose. Each later plan runs only its own widget with a grep on the tag in the test title (for example the playground tag) and turns it green. The full suite is run again only in plan 02.2-07.
- Hook names that later plans must create are fixed here so the check-dist self-test and the e2e specs agree: `data-six-text` on each list item of the "Read the six texts" list (value is the language id) and `data-six-texts` on its `<details>`; the languages widget root keeps `data-languages`; the playground chip lines keep `data-chip-main` (text line) and `data-chip-id` (ID line).
- The wrapper-structure locators in `e2e/languages.spec.ts` (`data-languages-card`, the section locator, `data-sentence` in the row header) cannot be made to match both the old and new markup without contortions. They are migrated in plan 02.2-06, together with the merge that changes them. They are listed there.
