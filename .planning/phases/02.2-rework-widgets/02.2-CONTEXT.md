# Phase 2.2: Rework widgets - Context

**Gathered:** 2026-10-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Redesign the interactive widgets in Post 1 so they look and behave consistently: constant height, wider than the reading column on wide screens, two columns on wide screens and stacked on narrow ones, no `.astro` wrappers (headings and prose live in the MDX, widgets are Svelte islands used directly), the languages table and its "Look inside" picker merged into one widget, and the playground showing token text and IDs together in one view (the "peek under the hood" toggle and the text/IDs toggle go away).

No new capability: tokenizer loading, the comparison content, the stepper's algorithm and the post's argument stay as built in Phases 2 and 2.1.

</domain>

<decisions>
## Implementation Decisions

### Height and width
- **D-01:** "Constant height" means **fixed per widget, reserved for its tallest state**, so nothing jumps while the reader uses it. Different widgets may have different heights. Applies in the two-column layout only (D-04). (Q-01 b)
- **D-02:** When content does not fit, **the affected panel scrolls inside the widget** (a labelled, keyboard-focusable region, as the stepper pair table already does). Other panels stay put. No input length cap. (Q-02 a)
- **D-03:** Widgets break out to **960px** wide on wide screens, centred on the 680px reading column; the width is capped at the screen width minus 48px. Chosen by viewing sketch 002 (variant A winner). The prose column stays 680px. (Q-03 custom, then sketch 002 A)
- **D-04:** **Two columns from 1024px up; below 1024px the widget stacks into one column and its height is automatic** (grows with content for readability). No horizontal page scroll at any width. (Q-04 b)

### Structure
- **D-05:** Column roles are **decided per widget**, within the rule that all of a widget's information is visible at once at two-column widths. (Q-05 c)
- **D-06:** **All `.astro` wrapper components are deleted** (`StepperSection`, `PlaygroundSection`, `ComparisonSection`, `LanguagesSection`, and the `LanguagesTable.astro` static table, which becomes part of the Svelte widget). Headings are plain `##` headings in the MDX. Each widget names itself with its own `aria-label`; no fixed heading-id link is required. Widgets are placed in the MDX as Svelte components with `client:` directives (playground keeps `client:load` per Phase 2.1 D-04; the others use `client:visible`). `PostLayout.astro`'s component map and the pinned-sentence tests in `post-content.test.ts` are updated together. (Q-06 b)
- **D-07:** Data the wrappers used to compute (the playground's pre-computed tokens for the default text and five examples, its size label, the licence-notices address built from the site base) comes from **one small shared `.ts` module that exports ready-made props**; the MDX only passes them. Islands still must not import the big fixture themselves, and nothing browser-only runs at module top level. (Q-07 b)

### Playground
- **D-08:** One view shows **both token text and token ID at once, as two-line chips** (text on top, ID underneath), in the same visual format as the stepper's character-over-byte stack. The text/IDs toggle and the "Peek under the hood" toggle are removed. (Q-08 a)
  - **Amended by the author (2026-10-11), overrides the text above:** the playground has a "Show token IDs" switch (`data-show-ids`), off by default. With it off, chips are text only, on one line. With it on, chips are text-over-ID stacked chips (the two-line chip). The text/IDs toggle is therefore back, which satisfies TOK-03 again. The "Peek under the hood" toggle and the whole-string byte view stay removed. The Words stat was removed by the author; the stats are Bytes, Characters and Tokens (words is still computed for the live screen-reader announcement). A verifier must not flag the switch, the one-line default chips, or the missing Words stat as deviations from D-08 or D-09.
- **D-09:** Hex bytes stay **on partial-character chips only** (FOUND-06 still holds; never a replacement symbol). The accessible text alternative table stays. The whole-string byte view is dropped. (Q-09 a)
- **D-10:** Post prose and pinned tests that mention the toggles are rewritten together, and those passages get a **human-gated non-programmer read-through** as a final task, as in Phases 2 and 2.1. (Q-10 b)

### Languages widget
- **D-11:** The languages table and the "Look inside" picker (`LanguagesDemo`) become **one Svelte widget**. The **comparison stays a separate widget** (it is not merged with languages). This supersedes the original brief's "merge ComparisonSection and LanguagesSection". (Q-11)
- **D-12:** A **readable table stays visible in the merged widget and is server-rendered**, so it works with no JS and for screen readers (Phase 2 D-14). (Q-12 a)
- **D-13:** The post keeps **both H2s** (comparison, languages). The languages prose is rewritten only as far as the merged widget needs. (Q-13)

### Verification
- **D-14:** **Playwright assertions** on the built site: each widget's height is identical across its states at one wide viewport, the layout stacks below 1024px, and no horizontal page scroll. Plus a **manual visual check at 360, 768, 1024 and 1440px**. (Q-14 b)

### Claude's Discretion

- Column roles per widget (D-05) and the stepper's block-to-column arrangement.
- Name and location of the shared props module (D-07).
- Whether shared layout CSS lives in `island.css` or a new file.

</decisions>
