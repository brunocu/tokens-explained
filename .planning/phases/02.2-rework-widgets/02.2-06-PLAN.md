## Goal

Merge the languages table and the "Look inside" picker into one server-rendered Svelte widget with the counts table across the full expanded width, and prove its height holds across every state.

Source: D-01 to D-07, D-11 to D-14; UI-SPEC "4. Languages" as amended by binding user decision 2; RESEARCH G-2 (languages), G-6; flags L-1, L-2.

## Flagged assumptions and planner choices

- Binding user decision 2 replaces the UI-SPEC's table-left, picker-right layout and the research options (a), (b) and (c) for this widget only: the counts table spans the widget's whole inner width (910px at 960px); the picker and the results are in a row below it.
- Layout chosen (the plan's judgement within that decision): the widget is a grid with two rows. Row one is one band across both columns: the lifecycle status line, the caption and the table, and nothing else. Row two has two columns, 5fr and 7fr. Lower left: the picker and the "What to notice" note (both natural height, neither scrolls). Lower right: one elastic scroll region ("Pieces for the chosen language, scrollable") holding the chosen language's text box, the two token rows, the legend, the tables details, then the "Read the six texts" details, the source line and the "Where the sentences come from" details. The research's concern about squeezing the table and the note into a narrow column no longer applies, because the table is full width.
- ASSUMPTION A-LANG-H (height behaviour, for the author to review): at 910px width the table is estimated at about 490px (a two-line caption of about 55px, a header of about 37px, five rows of about 62px and the Chinese row of about 86px). With the lower row, the widget needs roughly 900 to 1000px, which is above the 720px cap of the other widgets and taller than a 1440x900 laptop viewport (about 780px visible), so the reader scrolls the page while using this widget. The chosen behaviour is a fixed height with its own scroll region (D-01, D-02): starting value 960px, hard cap 1040px, set by measurement to the smallest multiple of 8 at which the table, the picker and the note are fully visible and the text box and the first English row show without scrolling; everything below scrolls inside the results region. The author may instead choose a smaller height (more scrolling in the results region) or a taller one by changing the one custom property; this plan does not decide that for the author. If the measured need exceeds 1040px, stop and report the numbers.
- Tab order in this layout: the table region, the picker, the "What to notice" note is not focusable, the results region (and, inside it, the tables summary, the six-texts summary and the sources summary). This replaces the UI-SPEC's list for this widget.
- Row headers hold the language name only (L-1), kept: the full-width table could hold the sentences, but at about 18px they would add several lines to every row and push the widget taller, so the sentences live in the right panel and the six-texts list.
- Hook names fixed in plan 01 are used here: `data-six-texts` on the details, `data-six-text` (value = language id) on each list item.
- The existing source line ends with a sentence pointing "above" at the comparison widget's tokenizer-file details; that widget stays above this one in the post, so the sentence stays true and is not changed.
