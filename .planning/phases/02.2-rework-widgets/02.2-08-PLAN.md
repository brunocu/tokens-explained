<interfaces>
Read the files; they win over this summary.

TokenRows.svelte: root `.rows` gets class `fill` when the `scroll` prop is set (Comparison sets it; LanguagesWidget does not). Each row is `div[role=group][data-row=gpt2|bert]` with class `fill` when scrolling, holding `.top` (header) and a ScrollRegion (`role=region`). The fill rules (grid of four tracks, subgrid rows, min-height 0, flex 1 1 0, the second row's 24px top padding) are unconditional, which is the root cause of G-02.2-1a: stacked, the card has no definite height, so the 1fr tracks collapse (measured at 390px: row 27.6px, region 34px, region scrollHeight 218px).

widget.css: the stacked form is the base; fixed height, the grid, `.widget-fill` flex and `.widget-scroll` overflow:auto are all inside `@media (min-width: 1024px)`. So stacked regions are already plain blocks; only TokenRows' own rules leak.

LanguagesWidget.svelte table: `table[data-languages-table]` with `caption`, `thead tr` (Language, Bytes, GPT-2, BERT, Text.sentence-col), `tbody tr[data-lang-row]` holding `th[scope=row]`, `td[data-bytes]`, two `td[data-count]`, and `td.sentence-cell[data-table-sentence]` (lang and dir set). Below 1024px the table has `min-width: 480px`, the five data columns are `width:1%; white-space:nowrap`, so the sentence column gets 60px at 390px (root cause of G-02.2-1b). The table sits in a `ScrollRegion xscroll padded={false}` named "Token counts by language, scrollable".

Playwright: the desktop projects (chromium, firefox, webkit) ignore `*.secondary.spec.ts`. `npm run test:e2e:secondary` runs the phone project (Pixel 7) over `**/*.secondary.spec.ts` and `smoke.spec.ts`; `phone-width.secondary.spec.ts` shows the pattern (`test.use({ viewport })`, `page.goto("what-is-a-token/")`, wait for `data-state="ready"`).

    Markup (minimal, all widths): add explicit ARIA roles to the elements whose CSS display changes, so table semantics survive in every browser (browsers have dropped native table semantics when a row or cell is given a non-table display): `role="row"` on both kinds of `tr`, `role="columnheader"` on the `thead th` elements, `role="rowheader"` on the `tbody th`, `role="cell"` on every `td`. Keep `scope`, `caption`, `table`, `thead`, `tbody`, every `data-*` hook, `lang` and `dir` exactly as they are, so check-dist.mjs and the existing specs need no change. If svelte-check with fail-on-warnings reports the redundant roles, add a `svelte-ignore a11y_no_redundant_roles` comment above the affected elements stating that the roles are deliberate because the stacked CSS changes the display of rows and cells.

    CSS: add one block `@media (max-width: 1023.98px)` after the existing rules (so min-width 1024px behaviour stays byte-for-byte what it is today and the boundary matches the 1024px min-width breakpoint). Inside it:
    - `table { min-width: 0 }` (the 480px minimum only existed to fit six columns; the xscroll region stays as a safety net)
    - each `tr` becomes a grid with four equal-purpose tracks: a wider first track and three equal ones, every track `minmax(0, ...)` with fixed fractions (about 1.5fr then 1fr 1fr 1fr) so columns align from row to row (do not use `auto` tracks, which size per row); the row separator moves to the `tr` as `border-top: 1px solid var(--border)` and the cells inside lose their own `border-top`
    - `th` and `td` lose the `width: 1%` and `white-space: nowrap` of the wide layout so "Chinese (Simplified)" can wrap; horizontal cell padding drops to `var(--space-sm)` so the three number columns fit at 360px; vertical padding unchanged
    - `.sentence-cell` spans all four tracks (`grid-column: 1 / -1`), keeps `text-align: start`, `unicode-bidi: isolate` and `overflow-wrap: anywhere`, loses its top border and takes a smaller top padding (`var(--space-xs)`) so it reads as part of its language's row, with enough bottom padding to separate it from the next row
    - the header row: the `Text` column header (`.sentence-col`) must not take a track or a line. Hide it visually in the standard visually-hidden way (absolute, 1px, clipped), with the header `tr` as the positioning context, so it stays in the accessibility tree and a screen reader still hears the column name; the other four headers sit in the same four tracks as the body rows so their labels line up with the numbers
    Row grid, spacing and the final fractions are the executor's call within these rules; measure at 390 and 360px and adjust until nothing is clipped. Do not add JavaScript, do not move the sentence text into a second element (it must stay the single `data-table-sentence` cell per row, six in total), and do not change any copy.

Run these against the unmodified LanguagesWidget first and expect (1) to fail with the 60px width, then implement the CSS and go green.
