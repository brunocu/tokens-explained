## Layout and Widget Sizing

### Breakout (D-03)

- The reading column is unchanged: `main { max-width: 680px }` (inner 632px at 640px and above).
- A widget is a direct child of `main`, placed by the MDX. Its **root element** carries the layout classes (`island-card widget`); a wrapper cannot carry them, because Astro renders a hydrated island inside `<astro-island>`, which is `display: contents`. Verify the class sits on a real box in the built HTML.
- From 1024px up: `width: min(960px, calc(100vw - 48px))` and `margin-inline: calc((100% - var(--widget-w)) / 2)` so the widget is centred on the 680px column and extends about 164px beyond each side of the text at 960px. Because the stacked layout covers everything below 1024px, the `100vw - 48px` cap is inert in practice (at 1024px the cap is 976px); keep it anyway as the stated safety rule. Never use `100vw` for anything else (it includes the scrollbar).
- Below 1024px: `width: 100%`, `margin-inline: 0` (no breakout).
- Vertical margin above and below the widget: 32px (xl), both modes.

### Breakpoint and stacking (D-04)

- `@media (min-width: 1024px)`: two columns, fixed height. Below: one column, `height: auto`, everything visible by growing, **no inner vertical scroll**.
- Stacked order is DOM order: left column first, then right column. Column order in the DOM is therefore the reading order on a phone and must be written that way.
- Stacked card chrome is the existing one: padding 16px (below 640px) or 24px (640px and above), gap 32px between blocks.
- Browser zoom to 200% or large system text drops the viewport below 1024 CSS px, so zoomed readers always get the stacked, auto-height form (WCAG 1.4.4 and 1.4.10 reflow).
- No horizontal page scroll at any width. A table that needs more room than its column keeps its own horizontal scroll inside a labelled region (existing pattern); the page never scrolls sideways.

### Two-column mode, the one grid every widget uses

```css
@media (min-width: 1024px) {
  .widget {
    --widget-w: min(960px, calc(100vw - 48px));
    width: var(--widget-w);
    margin-inline: calc((100% - var(--widget-w)) / 2);
    height: var(--widget-h);                 /* per widget, see below */
    display: grid;
    grid-template-columns: var(--widget-cols); /* per widget */
    column-gap: 24px;
    padding: 24px;
  }
  .widget-col { display: flex; flex-direction: column; gap: 16px; min-width: 0; min-height: 0; }
  .widget-fill   { flex: 1 1 0; min-height: 0; }      /* the one elastic element per column */
  .widget-scroll { overflow: auto; }                   /* an elastic region that scrolls */
}
```

At 960px the inner width is 910px; after the 24px gap the columns are about 369px (5fr) and 517px (7fr). Use `minmax(0, Nfr)` so a long chip or table cannot widen a column. `box-sizing: border-box` (the height includes padding and border).

### Fixed height (D-01, D-02)

- Each widget has one fixed `height` in two-column mode, reserved for **its tallest designed state**, so nothing about the widget's outer box changes while the reader uses it. The value is a custom property on the widget root (`--widget-h`).
- **Elastic rule:** in every column exactly one element is elastic (`.widget-fill`: a scroll region, or the textarea). Everything else in the column has its natural height. Conditional lines (loading, limit, error, "Try again") appear and disappear by resizing the elastic element, never the widget, and they sit **below** the content they qualify so the content above does not move.
- **Overflow rule:** content that does not fit never grows the widget and is never clipped. The affected scroll region scrolls; the other panels stay put. No input length cap beyond the existing 1,000-character limit (D-02).
- **Scroll region contract** (every `.widget-scroll`): `role="region"`, `tabindex="0"`, an `aria-label` ending in ", scrollable" (list under each widget), `--bg` surface with 1px `--border`, 4px radius, padding 16px (md), the global 2px accent focus ring. The edge shadow cue above. The widget itself has no `overflow: hidden`, so a focus ring or a descender is never clipped.
- **Scroll position:** when the content a region shows is replaced by a deliberate choice (example picked, language picked, stepper Next/Back/Run/Reset, Reset text), set that region's `scrollTop = 0` after the update. While the reader types, do not touch scroll position.
- **Starting heights (default; the executor measures):**

| Widget | Columns (left / right) | Start height | Left column role | Right column role |
|--------|------------------------|--------------|------------------|-------------------|
| Playground | 5fr / 7fr | 640px | Input: you act here | Output: tokens |
| Stepper | 5fr / 7fr | 680px | Controls and the explanation | The picture: words and pair table |
| Comparison | 5fr / 7fr | 720px | Input: pick or type a text, load BERT | Output: two tokenizer rows, note |
| Languages | 7fr / 5fr | 720px | The counts table (primary) | Look inside one language |

  The executor sets each value to the smallest multiple of 8 at or above the tallest designed state measured at 960px in Chromium (default text and the longest curated example in the playground and comparison; all 14 stages in the stepper; the longest-sentence language), **within 560 to 720px**. If a designed state would need more than 720px, the elastic region scrolls instead of the widget growing. On a 1440x900 laptop (about 780px of visible page) every widget fits whole; on a 1366x768 laptop (about 650px visible) the 680 to 720px widgets are slightly taller than the screen and the reader scrolls the page, which is accepted. Height does not depend on the viewport (rejected as Q-01 option c).
- **Guard:** no non-elastic content may overflow its column at default text settings. A Playwright check asserts `scrollHeight <= clientHeight + 1` for every `.widget-col` (Verification).

### Print

`@media print`: the stacked form (`height: auto`, `width: 100%`, `margin-inline: 0`, scroll regions `overflow: visible`, `break-inside: avoid` on the widget).

## Shared Chip Format (D-08, the stepper's stack as the model)

Per the D-08 amendment (author, 2026-10-11), the playground uses the stacked form only when its "Show token IDs" switch is on; with the switch off (the default) its chips are one line.

One anatomy, two scales. Both are **two lines, centred: the piece on top, its number underneath**, with a 2px outline, 4px radius and the shared palette. Extract it once (shared CSS in `island.css` as `.stack-chip`, or `Chip.svelte` extended and used by `TokenDisplay` and `BpeStepper`; planner's choice, but dimensions, fonts and borders are single-sourced and the palette is not duplicated).

| | Regular stack chip | Compact stack chip |
|---|--------------------|--------------------|
| Used by | Playground (`TokenDisplay` stacked form) | Stepper (`BpeStepper`) |
| Top line | token text, mono 18px / 400 / 1.4, `white-space: pre`, whitespace glyphs as today | piece text, mono 14px / 400 / 1.2, same glyph rule |
| Bottom line | ID, mono 14px / 400 / 1.4, `--ws-color`, `tabular-nums` | id, mono 14px / 400 / 1.2, `--ws-color`, `tabular-nums` |
| Padding / outline | 4px 8px / 2px | 4px / 2px |
| Height | about 57px | about 46px |
| Fill rule | alternating palette by position (`i mod 4`) | by meaning: byte = plain, learned piece = palette by `id mod 4` |

Rules that apply to both:
- **Playground, partial-character chip:** top line is the hex bytes (mono 14px, as today), bottom line is the ID. Hatched, dashed, inside its character frame (R-01) exactly as today. Hex stays on partial chips only (D-09, FOUND-06): never a replacement symbol.
- **Playground, normal chip:** no hex anywhere (the whole-string byte view is gone). The bytes remain in the text alternative table (Bytes column).
- **Special chip `[UNK]` / end-of-text:** unchanged style (neutral, solid). Comparison and language rows show them with no second line.
- Chips are not focusable, have no hover or tooltip, and their container stays `aria-hidden="true"`; the text alternative carries the content (Phase 1).
- Chips in a row stretch to the tallest chip of that row (`align-items: stretch`), so a row with a partial chip and a normal chip keeps even edges.
- **Comparison and language rows and the prose `TokenFigure` keep the existing one-line chip** (text only): D-08 is about the playground. IDs are not added there.
- Remove from `TokenDisplay`: the `mode="ids"` branch, the `showBytes` prop and the byte line under normal chips. One prop selects the one-line or the two-line form. `TokenFigure.astro` and `TokenRows.svelte` keep the one-line form.

## Verification Hooks (D-14)

Playwright on the built site (Chromium, Firefox, WebKit; the 360px checks live in `*.secondary.spec.ts` and do not gate):

1. **Constant height (1440x900, then 1280x800 and 1024x768):** for each widget, drive it through the states listed under its section and assert `getBoundingClientRect().height` is identical (within 0.5px) in every state.
2. **Breakout:** at 1440 and 1024, widget width is 960 (+/-1) and its left and right overflow past the `main` content box are equal (+/-1); at 1023 and 768 the width equals the `main` content width.
3. **Stacking:** at 1023 the right column's top is at or below the left column's bottom, and the widget has no fixed height (`height` equals its content height); at 1024 both columns share the same top.
4. **No horizontal page scroll:** `document.documentElement.scrollWidth <= clientWidth` at 768, 1023, 1024, 1440 (and 360, secondary), in every widget state that changes width (languages picked, tables open).
5. **Columns do not overflow:** each `.widget-col` has `scrollHeight <= clientHeight + 1`.
6. **Scroll regions:** every `.widget-scroll` has `role="region"`, `tabindex="0"` and an `aria-label` ending ", scrollable"; focus lands on it with Tab in the documented order.
7. **Removed controls are gone:** no `input[name="view"]`, no `[data-peek]`, no text "Peek under the hood" or "Token IDs".
8. **Stack chips:** in the playground every `[data-chip]` has a text line and an ID line; partial chips show hex on the top line; no hex line on normal chips; no U+FFFD anywhere; chip count still equals token count.
9. **Server-rendered output (`check:dist`):** the built HTML contains `data-chip` chips for the default text, the languages table with six `[data-lang-row]` rows and counts, the English drill-down rows, and the six texts, with no JavaScript.
10. axe in light and dark for each widget.

Manual visual check at **360, 768, 1024 and 1440px**, light and dark, each widget in its default state and its tallest state, plus 1280x720 as the laptop case: layout, scroll regions and their cue, chip format, that nothing is clipped, and that the post prose around the widget still reads at 680px.
