## Summary

The design is buildable with the existing stack, and the central CSS recipe works. A three-engine prototype (Chromium, Firefox, WebKit, at 1440, 1024, 1023 and 768 px) confirmed: the 960px breakout with `margin-inline: calc((100% - var(--widget-w)) / 2)` gives equal 164px overhang each side at 1440 and 1024; height is exactly the fixed value; the 5fr/7fr columns do not overflow; an elastic `<textarea>` and an elastic scroll region fill their columns; the stacked form below 1024 is auto-height; page `scrollWidth - clientWidth` is 0 at every width; the `background-attachment: local` + `color-mix()` scroll cue parses in all three engines.

Three findings change the plan, and one is a hard build rule. (1) **Hard rule:** in Astro 7's MDX pipeline a component with a `client:` directive must be imported in the MDX file itself, and the import must come *before* its first use; the `components` map in `PostLayout.astro` cannot supply hydrated islands. That forces a rewrite of the "closed component vocabulary / no import lines" test. (2) **Layout feasibility:** measured heights show the UI-SPEC's languages left column (and, less severely, the stepper right column and the comparison right region) cannot show everything at once inside the 560-720px cap; the planner needs a decision on what moves or scrolls. (3) **Test migration is larger than UI-SPEC "Test impact" lists**: more e2e files and `check-dist.mjs` pin the wrappers, heading ids and the removed controls.

**Primary recommendation:** Import the four islands and one props module at the top of the MDX; gate every `.widget-fill`/`.widget-scroll` rule behind `@media (min-width: 1024px)`; resolve the languages-column budget (below, G-2) before writing that plan; budget a dedicated Wave 0 "test migration" task for the files listed in G-3.

## Findings (the gaps)

### G-1. Islands must be imported in the MDX, at the top; the `components` map cannot carry them [VERIFIED: scratch build]

Probe: a scratch copy of the repo (`.../scratchpad/proj`), `PostLayout` map extended with `BpeStepper` and `Comparison`, MDX using `<BpeStepper client:visible />` with no import. Build failed:

```
Expected a matching import for component `BpeStepper`. Did you forget to import it?
```

Source of the rule: `node_modules/@astrojs/markdown-satteri/dist/mdx/hast-astro-metadata.js` throws exactly that string in `processJsxNode` when `findMatchingImport(tagName, imports)` finds nothing [VERIFIED: hast-astro-metadata.js:61-71, read this session]. The `imports` map is filled by an `mdxjsEsm(node)` visitor *as the document is walked* (`createAstroMetadataPlugin`), so **an `import` placed after the first use of the tag also fails** (second probe failed the same way until all imports were moved directly under the frontmatter). Moving the imports to the top gave a clean build with five `<astro-island ... client="visible|load">` elements, props serialised, and the islands emitted as direct children of `<article>` (not inside a `<p>`).

Consequences for the plan:
- `PostLayout.astro`'s component map only keeps the *static* prose components (`TokenFigure`, `Fact`, `Cite`, `References`, `Reference`, `TextAsNumbers`). Remove the four wrapper entries and the four wrapper imports.
- The MDX gets a block of `import` lines directly after the frontmatter: `BpeStepper`, `Playground`, `Comparison`, the new languages widget, and the props module.
- `src/content/post-content.test.ts:388` pins the opposite: `it("uses a closed component vocabulary: no import lines, only the registered components", () => {` and asserts `raw.split("\n").some((line) => line.startsWith("import "))` is false [VERIFIED: post-content.test.ts:388-390]. Rewrite it to: imports allowed only at the top, only from an allow-list of paths; component names allowed = the static map plus the four islands. Keep the "no other component" spirit.
- `scripts/check-repo.mjs` scans `.mdx` for banned constructs (`innerHTML`, `fetch(`, `localStorage`, ...) [VERIFIED: check-repo.mjs:11-34]; import lines do not trip it.

### G-6. CSS recipe pitfalls (all verified in the three-engine prototype)

- The breakout rule must be on the **component root**, because `astro-island` is `display: contents` (`astro-island,astro-slot,astro-static-slot{display:contents}` is in the built HTML) [VERIFIED: dist-b HTML]. UI-SPEC already says this; confirmed. The root's containing block is `<article>`, so `100%` in the margin formula resolves to the 632px content width.
- `.widget-fill { flex: 1 1 0; min-height: 0 }` and `.widget-scroll { overflow: auto }` **must live inside the `@media (min-width: 1024px)` block** (as the UI-SPEC snippet shows). If they are written outside it, the stacked card (`display:flex; flex-direction:column; height:auto`) collapses the fill element to its `min-height` and the content is clipped or scrolls in the stacked layout where UI-SPEC requires no inner scroll. In the prototype the stacked textarea correctly fell back to `min-height` and the scroll region to natural height only because the rules were scoped.
- `.island-card` currently has `gap: 32px` and padding 16/24px. The two-column grid needs `gap` replaced by `row-gap: 0; column-gap: 24px` (or equivalent) at ≥1024px; do not leave the 32px gap on the grid.
- Print: `@media print` must reset `height`, `margin-inline`, `width`, `overflow` (UI-SPEC lists it); easy to forget because the fixed height is set via a custom property.

## Architecture Patterns

### Data flow

```
what-is-a-token.mdx
  imports (top of file, before first use)
      |-- BpeStepper.svelte      --> <BpeStepper client:visible />
      |-- Playground.svelte      --> <Playground client:load {...playgroundProps} />
      |-- Comparison.svelte      --> <Comparison client:visible {...comparisonProps} />
      |-- LanguagesWidget.svelte --> <LanguagesWidget client:visible />
      '-- postProps.ts (Node only: fixture + BASE_URL --> plain objects --> astro-island props attr)
  plain "## Heading" + prose between them (MDX), static prose components from the PostLayout map

Build: Svelte SSR renders each widget root (class "island-card widget", data-island) inside <astro-island> (display: contents)
Browser >= 1024px: root becomes grid, 960px, fixed height; <1024px: flex column, auto height
Hydration: client:load (playground) / client:visible (others) flips data-state loading -> ready
```

### Pattern: scoped layout CSS

Use the UI-SPEC "one grid every widget uses" block unchanged, with `.widget-fill`/`.widget-scroll` inside the media query. Prototype that was run in Chromium, Firefox and WebKit (widths 1440, 1024, 1023, 768) used exactly that block plus a `local`/`scroll` background-attachment cue.

### Anti-patterns
- Putting islands in the `components` map and writing `<Playground client:load />` with no import (build error, G-1).
- Importing the props module from any `.svelte` file (pulls the fixture into the island, G-5).
- Setting `flex: 1 1 0` / `overflow: auto` outside the 1024px media query (G-6).

## Don't Hand-Roll

| Problem | Don't build | Use instead | Why |
|---------|-------------|-------------|-----|
| Scrollable labelled region | six copies of `role=region tabindex=0 aria-label` | one `ScrollRegion.svelte` | single svelte-ignore, single focus/scroll-reset contract |
| Equal-height assertions | custom screenshot diff | Playwright `getBoundingClientRect().height` equality (D-14) | height is a definite CSS value, so equality is exact in all three engines |
| Column overflow guard | manual measuring | `scrollHeight <= clientHeight + 1` per `.widget-col` (UI-SPEC hook 5) | directly detects non-elastic content overflowing |

## Common Pitfalls

### Pitfall 1: Import after first use
**What goes wrong:** build error "Expected a matching import for component".
**Why:** Sätteri's metadata plugin builds its import table in document order (G-1).
**Avoid:** all imports directly under the frontmatter. **Detect:** `npm run build`.

### Pitfall 2: Stacked layout collapses
**What goes wrong:** below 1024px a textarea or region is 0-96px tall or clipped.
**Why:** `flex: 1 1 0` on a child of an auto-height column (G-6).
**Avoid:** keep every fill/scroll rule inside the media query; verify the 1023px and 768px stacked-height assertion (UI-SPEC hook 3).

### Pitfall 3: Orphaned scoped CSS fails `check:svelte`
**Why:** `--fail-on-warnings` (G-7). **Avoid:** delete CSS with the markup it styled.

### Pitfall 4: Table `min-width: 600px`
**What goes wrong:** the languages table gets its own horizontal scroll at the 517px column, hiding the BERT column.
**Avoid:** remove `min-width` and set the first column to ~22% (G-2).

### Pitfall 5: Fixed heights set from the UI-SPEC starting values
**What goes wrong:** regions scroll in the default state of the languages and stepper widgets (G-2).
**Avoid:** take the measured numbers in G-2 as the starting point, not 640/680/720/720.

### Pitfall 6: Raw-bytes and Peek strings left in tests or prose
UI-SPEC hook 7 requires no `input[name="view"]`, no `[data-peek]`, no "Peek under the hood", no "Token IDs". Grep `e2e/`, `src/`, `scripts/` for those strings and for `data-chip-bytes` at the end of each plan (G-3 list).
