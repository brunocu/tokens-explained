## Goal

The playground becomes the first converted widget, end to end: shared layout CSS, the scroll-region component, the shared props module, the MDX import block, the layout's component map, and the Svelte island in its two-column form, with the toggles removed. Then the two-line chip, which this widget and (in plan 04) the stepper share.

Source: D-01 to D-09; UI-SPEC sections "Layout and Widget Sizing", "Shared Chip Format", "1. Playground"; RESEARCH G-1, G-5, G-6, G-7.

## Flagged assumptions and planner choices

- Tracer-first: Task 1 is the tracer. It carries one widget through every layer the phase touches (CSS, shared component, props module, MDX, layout map, island, tests). The other three widgets expand from it in plans 04 to 06.
- Per-widget values are set on the widget root inside the component's own scoped style (`--widget-h`, `--widget-cols`), not in `widget.css`, so later plans do not edit the same CSS file. Starting height for the playground is 640px; plan 03 measures and sets the final value within 560 to 720px.
- The new props module is `src/components/postProps.ts` (the location the research probe verified). It holds only `playgroundProps` in this plan; plan 05 adds the comparison's props.
- Chip palette: the stacked-chip anatomy (padding, lines, fonts, outline, radius) is single-sourced in `widget.css` as `.stack-chip` with a regular and a compact modifier. Fill and line colours come from the same `--chip-N-*` and `--partial-*` custom properties as today, so no colour value is duplicated. Plan 04 adopts the compact modifier in `Chip.svelte`.
- The one-line chip form (comparison rows, language rows, the prose figure) is unchanged (UI-SPEC: D-08 is about the playground).
- Between Task 1 and Task 2 the chips on screen are still one-line; the helper sentence "Each chip shows a piece of text with its ID number underneath." is added in Task 2, when it becomes true.
- The playground e2e specs that drove the removed controls are migrated in plan 03; until then they are red, and this plan's verify runs only the layout spec for the playground, the post spec and the unit tests.
