# Phase 2.2 Plan 03: Playground lifecycle copy, spec migration and height proof Summary

**The playground now reads in neutral wording, every spec that drove the removed Show and peek controls is rewritten for the two-line chip, and a seven-test layout suite proves the widget's height equals its declared 656px in every designed state on Chromium, Firefox and WebKit.**

## Measurements (Chromium, 1440x900)

Widget chrome: padding 24 + 24 and border 1 + 1 = 50px, so a column's inner height is the widget height minus 50.

| Quantity | Measured |
|----------|----------|
| Left column parts, default state | label 19.6, textarea 242 (elastic), notes 47.2, examples 175.6, counts 49.6 |
| Left column, download failed (notes 158px) | needs 562.75 at textarea 96 (before the label pull-up) |
| Left column, download failed plus limit message (notes 205.2px), the tallest | parts and gaps 609.9px at the 96px textarea floor; less the 8px the label is pulled up = 601.9px |
| Widget height needed | 601.9 + 50 = 651.9px, so the next multiple of 8 is 656px |
| Check at 640px (old value) | column overflows by 12px in that state |
| Check at 648px | column overflows by 4px |
| Check at 656px (chosen) | no column overflows, textarea at least 96px, in all three engines |
| Right column, non-elastic parts | tokens head 48.4px, legend 61.6px, two 16px gaps: needs 342px with the region at 200px (the region is 464px tall at 656px in the default state, 200px is the minimum asked for) |

**Chosen `--widget-h`: 656px** (a multiple of 8, inside 560 to 720px). The playground's tallest left-column state fits; nothing needed the 720px cap.

## Accomplishments

- **Copy (W-1):** the loading, failed and no-JS sentences in `Playground.svelte` no longer point "below" at content that now sits beside the controls; `states.spec` tests (e) and (f) quote the new sentences.
- **Spec migration (D-08, D-09, D-10):**
  - `controls.spec`: deleted the examples-keep-settings, IDs-view, peek and keyboard-between-views tests; added (c) two-line chips after every example and Reset, and (d) each chip's ID equals the table's ID column in order, with the counts unchanged by opening the table (also checked on the emoji example, which has partial chips). The 44 by 44 list drops the Show segments and the peek switch and gains the table summary.
  - `frames.spec`: (d) rewritten as "the two-line chip leaves the frames unchanged, with the label centred"; (e) proves the four whole chips from their text lines (女, ん, に, は), their numeric ID lines, and the table's Bytes and ID cells for the same rows.
  - `a11y.spec`, `privacy.spec`, `phone-width.secondary.spec`: toggle clicks removed; the privacy no-request assertions are kept.
  - `states.spec` (h): Tab walk is textarea, five examples, Reset text, the tokens region (by its accessible name), the table summary.
- **Height proof (D-01, D-14 hook 1):** `expectHeightEquals` plus seven `@playground` tests. Height equality across default text, five examples, Reset, empty text, a 1,000-character paste, table open and closed, at 1440x900, 1280x800 and 1024x768; tokenizer loading and ready; download failed (error and Try again below the textarea inside the left column, textarea at least 96px, no column overflow, then the limit message added as well); island never hydrates (Reload page in the left column, textarea at least 96px); no JavaScript (chips, counts, table present, controls locked, height equal).
- **Chip format (hook 8):** on the non-English and emoji examples every chip has exactly a text line and an ID line, partial chips have a hex top line, whole chips do not, the chip count equals the table's row count, no U+FFFD in the widget.
