# Phase 2.2 Plan 05: Comparison rework Summary

**The comparison is a 720px two-column widget: picker, text box and BERT download on the left, the GPT-2 and BERT rows in a scroll region with the "What to notice" note anchored below it on the right. Its height holds across every state in three browsers.**

## What was done

- **Task 1** (`c1fb382`). `Comparison.svelte` is now a `section` with `widget--comparison` (5fr/7fr, 720px) and all existing hooks. Left column: status line, picker, label and text box (static box until GPT-2 is ready, then the textarea; both elastic with a 96px floor in the two-column form), a `.notes` block (loading line or error with Try again, privacy line, limit message, "Use the example text again"), then the BERT block with its idle paragraph in the 14px muted label size. Right column: a `ScrollRegion` named "Tokenizer rows, scrollable" holding the rows, the shared legend, the "BERT is on its way" line, the tables details and the provenance, reset by a counter that changes only on a picker choice or "Use the example text again"; below it the note, shown only while the text is an unedited example. `comparisonProps` was added to `postProps.ts` and tested. The MDX imports `Comparison` and places it with `client:visible` under `## How does GPT-2 compare with other models?` after the word-for-word lead-in. The wrapper file is deleted and removed from `PostLayout.astro`. The content test's headings, order markers, per-tag loop, lead-in pin and closed tag set moved together.
- **Task 2** (`c6893f5`). Migrated `comparison.spec.ts` (neutral sentences, rows-region locator) and `comparison-load.spec.ts` (one locator), with request-count and focus assertions untouched. Added twelve `@compare` tests to `widget-layout.spec.ts`: constant height (five examples, edited text, emptied text, "Use the example text again", tables and source details open and closed) at three viewports; script loading and never hydrating; no JavaScript; GPT-2 loading; GPT-2 failed (error and Try again under the text box, text box at least 96px, no column overflow); BERT idle, loading, ready and ready with typed text; BERT failed; no sideways page scroll with both details open at four widths; the rows-fit guard; and a record-only test.

## Rows-region scroll record (1440x900, region 720px widget)

The guard passes for all five examples: both rows and the shared legend sit fully inside the visible area with the region at its top. What scrolls is the secondary content (tables details and provenance). Chromium and WebKit agree exactly; Firefox is 1 to 2px taller.

| Example | Rows region scrolls? | scroll / client (Chromium) | Legend bottom from region top | Note height |
|---------|----------------------|----------------------------|-------------------------------|-------------|
| rare-word (the default) | yes, by 173px | 740 / 567 | 518px | 58px |
| numbers-dates | yes, by 120px | 658 / 538 | 435px | 86px |
| emoji | yes, by 118px | 656 / 538 | 433px | 86px |
| literature | yes, by 202px | 740 / 538 | 518px | 86px |
| non-english | yes, by 79px | 617 / 538 | 394px | 86px |

The default state (the first example, "A rare long word") therefore shows a small scroll in the rows region because the provenance is below the fold, as the plan expected. The literature example is the tightest: its legend ends 20px above the region's visible bottom. No note needed shortening, so `notes.ts` and its test are unchanged.
