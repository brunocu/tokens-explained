# Phase 02 Plan 05: Comparison fixture, languages and notes Summary

**A committed, dated fixture of toy, GPT-2 and BERT token rows for the five playground examples and the six-language UDHR Article 1, generated by one script with a `--check` mode, guarded by a freshness test, plus the sources, row names and hand-written notes the comparison page will show.**

## Accomplishments

- Tracer (Task 1): `npm run precompute:comparison` runs `EXAMPLES` through the toy and both real tokenizers (real files from `public/tokenizers/`, adapter from 02-02) and writes `src/core/compare/comparison.json` with the generation date, the toy merge count and sha256, the GPT-2 and BERT repo, commit, licence and sha256 from the manifest, and the download label (0.7). `-- --check` exits non-zero if the committed file differs, ignoring only `generatedAt`. The tracer gate (end-of-phase mode, automated verify only) was re-run end to end and passed before the expansion tasks.
- Freshness test: rebuilds the fixture through `buildComparison` and requires both object equality (minus date) and an exact match with the committed text, so a retrained `merges.json` or a changed tokenizer file cannot leave stale numbers (T-02-12).
- Languages (Task 2): the whole of Article 1 in English, Spanish, French, Russian, Arabic and Chinese (Simplified). Every string was re-extracted from its un.org page (NFC) and equals `languages.ts` exactly; English, Spanish, French and Russian also match the OHCHR PDF text, and all 39 Han characters of the Chinese match `chn.pdf`. Code-point counts 170, 171, 186, 160, 123, 43 are pinned.
- Pinned counts hold: GPT-2 and BERT for the five examples (16/16, 19/19, 9/7, 26/26, 10/7) and the six sentences (33/32, 58/57, 61/61, 172/133, 121/101, 86/43); BERT Chinese has 25 `[UNK]` of 43, every other language 0; the emoji example has exactly two special tokens.
- Names and notes (Task 3): `TOKENIZER_ROWS` ("GPT-2 (2019)", "BERT, uncased (2018)", amended BERT subline with "removes accents") and `NOTES` (five examples) plus `LANGUAGES_NOTE`, each at most two sentences, no digits apart from the name GPT-2, no other vendor names, written from the actual rows.

## Fixture shape (read by plans 02-06 to 02-08)

`src/core/compare/comparison.json`, typed as `ComparisonFixture` in `src/core/compare/fixture.ts`; import it as `COMPARISON` from `src/core/compare/comparison.ts`.

```
{
  meta: {
    generatedAt: "YYYY-MM-DD",
    toy: { merges: 800, mergesSha256 },
    tokenizers: { gpt2: { repo, commit, license, sha256 }, bert: { repo, commit, license, sha256 } },
    download: { combinedGzipBytes: 739621, sizeLabelMb: "0.7" }
  },
  examples:  [{ id, label, text, rows: { toy, gpt2, bert } }],   // 5, in EXAMPLES order
  languages: [{ id, rows: { toy, gpt2, bert } }]                 // 6: en, es, fr, ru, ar, zh
}
// each row is FixtureToken[] = { id: number, hex: "54 68 65", special?: true }
```

- `fixtureTokens(rows)` turns a row back into `Token[]` (bytes parsed from hex; `isPartial` computed; special tokens never partial) so `TokenDisplay`, `chipText`, `groupBytes` and `tableCell` work unchanged. `countUnk(tokens)` counts `[UNK]`. `tokensToFixture` is the inverse used by the builder.
- Sentences, language names, `lang`, `dir`, retrieval URL and date, and the OHCHR PDF live in `languages.ts` (`LANGUAGES`, `SOURCE_PAGE`), not in the fixture.
- Display names and sublines: `TOKENIZER_ROWS`. Notes: `NOTES[exampleId]`, `LANGUAGES_NOTE`.
- The "Precomputed on {date}" line reads `COMPARISON.meta.generatedAt`; "commit 607a30d" / "86b5e09" are the first seven characters of `meta.tokenizers.*.commit`.

## Decisions Made

- Hex bytes, not text, in the fixture: partial characters, spaces and `[UNK]` all round-trip without a replacement character or a raw GPT-2 glyph.
- The language sentences stay out of the fixture (one place to correct them, as the plan says).
- The note test strips "GPT-2" before checking for digits, since the plan requires both "no digits" and the name GPT-2.

### Notes written against the data (D-13)

- **Emoji note differs slightly from the UI-SPEC intent.** The intent says byte-level tokenizers (toy and GPT-2) split the emoji into byte pieces. The data shows GPT-2 splits the first emoji into byte pieces (`20 F0 9F`, `8E`, `89`) but has a single piece for the second (`␣🙂`). The note says exactly that. BERT shows `[UNK]` twice, as intended.
- **Non-English note differs from the intent.** The data shows the toy uses only raw byte pieces, GPT-2 mixes whole pieces (女, ん, に, は) with byte pieces, and BERT has a piece per character (with `##` on later ones), so the note says so rather than the more general intent wording.
- **Numbers note** says the toy cuts most digits one at a time while GPT-2 and BERT mostly keep short runs together, which the rows show; it carries no figures.
