## Phase Goal

**As a** reader with no programming background, **I want** to type my own text and see the toy, GPT-2 and BERT cut it, **so that** I can test the idea on text I care about, without anything leaving my browser.

Source: ROADMAP criterion 3 (reader comparison), D-09 to D-11, UI-SPEC section 2 "Own-text block", RESEARCH Gaps 4 and 8, Pitfalls 1 and 3.

## Flagged assumptions and planner choices

- RESEARCH A1: the Playwright route-abort pattern for the retry test is standard usage; the executor confirms it in the run.
- The loader lives in `src/components/loadTokenizer.ts` (not `src/core`) because it uses the network and Vite's base; `src/core` stays loadable by native Node.
- No runtime hash check of the downloaded JSON: the files are same-origin, committed and hash-tested at build; a runtime check adds code for no stated threat (T-02-24 accepted).
- This plan adds a new wave (6) because it shares `e2e/a11y-phase2.spec.ts` with plan 02-07.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reader text to tokenizers | Untrusted text goes to a third-party library inside the reader's own browser; it never leaves it |
| site origin to browser | Two same-origin JSON files are downloaded on request |
| repo lint to src | check:repo relaxes the network-call ban for one file |
