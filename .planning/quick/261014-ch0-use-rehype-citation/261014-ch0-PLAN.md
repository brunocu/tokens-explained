Locked decisions (numbered here in the order of the CONTEXT file):
- D-01 Pipeline switch: install `@astrojs/markdown-remark` and set `markdown.processor: unified({...})` globally (leaves Satteri).
- D-02 Citation style: a built-in style, no custom CSL. The context names "ieee/vancouver", but rehype-citation 2.3.2 ships only apa, vancouver, harvard1, chicago and mla (verified in the package `dist/node/styles`); there is no built-in ieee. So use `vancouver` (the only built-in numeric style). Readers will see "(1)" in text and "1." in the list instead of "[1]". Wording changes in entries are accepted.
- D-03 Bibliography source: a BibTeX `.bib` file at `src/data/references.bib` (Claude's discretion on location).
- D-04 Migration: replace fully. Convert prose to `[@key]`, delete the Cite / References / Reference components and their test coverage.

Verified facts that shape the plan (scratch Astro 7.3.5 + @astrojs/mdx 8.0.2 + @astrojs/markdown-remark 7.3.2 + rehype-citation 2.3.2 build, this session):
- `[@key]` in `.mdx` renders `<span class="cites" id="citation--key--N">(<a href="#bib-key">N</a>)</span>` when options are `csl: "vancouver"`, `linkCitations: true`, `inlineClass: ["cites"]`. The bibliography renders as `div#refs.references.csl-bib-body` with `div.csl-entry#bib-key` children, each holding `div.csl-left-margin` ("1. ") and `div.csl-right-inline`. A `[^ref]` paragraph under the heading places it there. The URLs inside are plain text, not links.
- GROUPED CITES ARE MISLABELLED unless written in ascending citation-number order: citeproc sorts the visible numbers ascending but the links stay in written order (for example `[@sennrich; @tiktoken]` after both were numbered 15 and 22 rendered "1,2" with the links swapped). Therefore every group must be written in ascending order of first-citation number, and a test must enforce it. The old post has exactly one out-of-order group (old numbers 15 then 7): write it as 7 then 15.
- A key missing from the .bib is left in the page as literal `[@key]` text with no build error; a test must catch this.
- "and others" in BibTeX renders as an author named "others". For the old entries that say "et al." use a braced literal author in Vancouver form with no trailing period (for example `{{Aduriz I, et al}}`) so no author list is invented. A `note` field and `translator` are not printed by vancouver; put the translator in the Anna Karenina title.
- `@astrojs/mdx` 8.0.2 has an optional peer `@astrojs/markdown-remark ^7.3.0`, satisfied by 7.3.2. Latest on npm: rehype-citation 2.3.2 (MIT, one maintainer, no install scripts), @astrojs/markdown-remark 7.3.2 (MIT, withastro). The scratch install flagged install scripts only for esbuild (already in the tree via Astro) and fsevents.
- `check-dist` only polices `href`/`src`-style attributes, so plain-text URLs would pass it, but the old list had clickable links and the e2e checks require them; the small `rehypeLinkUrls` plugin keeps that behaviour (anchors with `rel="noopener noreferrer"`).
